## 2. 事实错误（1 项，必须改）

### E1 — 时间总计错了

他写「今日时间结构（**5h40m**）」。

核对：
```
manifest daily_blocks = [20, 70, 140, 60, 40, 30]
总计 = 360 分钟 = 6.0 小时
daily_hours 字段 = 6
他写的 5h40m = 340 分钟
```

差 20 分钟。**这个数字 `bootcamp.py today` 的输出里就有，属于可直接核对却手算了。**

在这个仓库里这类错误要被指出——因为整套训练的前提就是「数字要能回溯到源」。

## 3. 系统性遗漏（4 项）——本次 review 的真正发现

他复述了**规则层**（P1 / R1 / 欠账表），但漏掉了**设计层**：worksheet 里那些被特意标为「关键」「否则没做完」「顺序反了就废」的地方。

| worksheet 原文 | 强度标记 | 他的处理 |
|---|---|---|
| `00` line 14：**禁止使用「护城河」「moat」「壁垒」三个词** | Part A 硬规则 | ❌ 完全漏。他只在 Part B 提了「不准统称 moat」 |
| `00` line 82：「这一栏答不出来，**Day 2 就没做完**」（B6 complementary assets） | 八维度里唯一的 must-answer | ❌ 漏。八维度被平铺处理，没有突出胜负手 |
| `00` line 219：「**Part C2 是今天的关键闭锁**…顺序反了这个练习就废了」 | 当天核心设计 | ⚠️ 降级。他写成「只对照你的 C2」，把闭锁说成了对照对象 |
| `03` line 55：`**BLOCKED by #2**`（#3 用哪个口径判断 rent，依赖 #2） | 与欠账 B/C 同源的依赖记录 | ❌ 漏。他提了欠账表里的 B/C，没提队列里的同一件事 |

### 为什么这四项重要

- **三词禁令**是今天最有教学价值的约束：逼你说机制而不是贴标签。漏了它，Part A 大概率会写出「因为切换成本高，护城河深」这种句子，练习效果减半。
- **B6 是 Teece 的胜负手**。八维度平铺会让人平均用力，而实际上「谁控制 cospecialized complementary assets」这一条决定 rent 归属，其余七项都是它的表现形式。
- **C2 是闭锁不是对照**。说成「对照」意味着你可以先看素材再写，那就把 counterfactual removal 练习废掉了。
- **BLOCKED 依赖**是我特意在两处（欠账表 + 队列）做的双记录，防止单点丢失。他只搬了一处，双记录的冗余设计失效。

## 4. 判断漏洞（1 项）

### E2 — 「九种交互模式随时可调用」是不准确的

他写：「随时可被点名调用九种交互模式（考我 / 只告诉我差在哪 / 只要事实……）」

问题：**闭卷未提交时这些模式不是全部可用。**
如果 owner 说「考我今天的八维度」，Examiner 模式就变成了绕过闭锁拿提示的通道。

**这个漏洞一半责任在我** —— 原 `METHOD_interaction_modes.md` 和 AGENTS.md §4 都没写这个限定。
已修复：新增 **R8**，并在两份文档里补了可用性矩阵。判据是「**会不会泄露当天闭卷题的答案结构**」。

## 5. 风格问题（不影响正确性）

开头三句是过程自述：

> 「我先按 AGENTS.md 的规定，接管时跑状态命令…」

不算违规，但如果每天都这样，20 天会累积成噪音。
