## 3. 中途发现的问题（按类别，含证据）

### 3.1 时间估算系统性偏低 → v1 废止的直接原因
- 计划：60 分钟/天读完材料
- 实测：Teece + Baker & Smith 单独就要 3–4 小时；全部材料需 90–125 小时
- 缺口：4.5–6 倍
- **根因**：v1 设计时用"论文页数"估算，没有用"owner 实际精读速度"校准

### 3.2 完成度自评偏差 → 固化为 R1
- Day 1：owner 两次声称"已完成"，实际都有未完成项（第一次 Part B/C 空白，第二次 unknowns 清单全空）
- **判定**：这不是不诚实，是自评偏差——恰恰是训练要消除的东西
- **教训**：AI 侧的核实动作不能信任声明，必须逐文件读取内容后用表格列出"声明 vs 实际"

### 3.3 多 agent 交接的设计层遗漏 → 固化为 R7/R8
另一 agent 接管 Day 2 时，**流程性核实全部通过**（文件存在、字段填了），但**设计层约束全部漏掉**：
| worksheet 原文 | 强度标记 | 是否传达 |
|---|---|---|
| 「禁止使用『护城河』『moat』『壁垒』这三个词」 | Part A 硬规则 | ❌ 漏 |
| 「这一栏答不出来，Day 2 就没做完」（B6 complementary assets） | 唯一 must-answer 项 | ❌ 漏 |
| 「Part C2 是今天的关键闭锁，顺序反了这个练习就废了」 | 当天核心设计 | ⚠️ 降级为一般对照 |

**教训**：核实分两层——完成度（填了没有）和设计意图（哪些约束被标为"关键/否则没做完/顺序反了就废"）。前者容易复述，后者才是当天训练的真正形状，也最容易被漏掉。

### 3.4 练习开放度过高 → Baldwin control-point map 改造
- 原设计：开放式"control-point map"（owner 自己找一个案例，画出 bottleneck 迁移）
- owner 反馈：**题目太开放，无从下手**
- **改造方案**：结果已知、但分轮隐藏证据的历史案例（IBM PC Guided Lab 01）——1981 年信息集闭卷押注 → 1983–84 证据 → 1991 结果，三轮释放
- **教训**：「开放式探索」和「结构化但独立判断」不是同一件事。对已有强分析能力的 owner，真正缺的往往不是"选题自由度"，而是"押注-验证"的反馈循环——开放式作业反而削弱了这个循环，因为没有已知答案可供校准误差。

### 3.5 阅读顺序会污染独立判断
- 原计划：读完 Henderson & Clark（architectural innovation 理论）再做 IBM PC Lab
- 调整：Lab Round 1 先做，H&C 排在 Round 1 提交之后
- **理由**：IBM PC 是 architectural innovation 的教科书案例，先读理论会让 owner 的押注变成"套用理论"而不是"独立识别模式"，顺序反了这个练习就作废
- **教训**：理论材料与其对应的经典案例练习之间存在"污染窗口"，课程设计必须显式排序，不能假设"读完理论再练习"永远是对的默认顺序

### 3.6 g1 闸门（材料占比≤50%）擦边超限
- 新增 Henderson & Clark + Jacobides & Winter 两篇论文后，M1 材料时间 10.5–14.5h vs 上限 11–14h（est 的 50%）
- **判定**：诚实报告为"算术冲突"，不得靠上调 est_hours 来掩盖——这正是 v1 失败模式（材料挤掉应用）的重演风险
- **处理**：一旦再读任何 jit_pool 论文即超限，届时必须停止读材料转入应用

## 4. 已固化的设计规则（供未来课程复用）

### 4.1 三防失控闸门（脚本强制执行，v2 实测有效）
| 闸门 | 规则 | 执行方式 |
|---|---|---|
| g1 | 材料时间 ≤ module 总时间 50% | `modules.py log` 超限即告警 |
| g2 | module 以"闭卷跑通框架 + 匿名 transfer test"出口，不以"读完"出口 | 人工判定 |
| g3 | 每 module ≥3 条可结算预测 | `modules.py exit --pass` 会拒绝不满足的出口 |

### 4.2 R1–R8 操作规则（AGENTS.md §3，摘要）
| 规则 | 一句话总结 |
|---|---|
| R1 | 完成声明必须逐文件核实，不信声明 |
| R2 | Orientation pack 七件必备：边界声明/栏目图例/多口径并列/争议数据表/gap清单/对照检查清单/primary source |
| R3 | Reconciliation checker 只报差异不报原因，污染判断要显式冻结 |
| R4 | 问题形态诊断不代写问题，好问题三检验：可观测/可结算/load-bearing |
| R5 | 判断列永远留给 owner（AI 填事实/证据/口径/缺口，owner 填判断/概率/脆弱点） |
| R6 | 区分"猜对了"和"无法验证"，不能混在一起制造虚假信心 |
| R7 | 核实分两层：完成度 + 设计意图（后者最容易漏） |
| R8 | 闭卷未提交时，九种交互模式不是全部可用，判据是"是否泄露当天答案结构" |

### 4.3 四条硬约束（不可协商）
- P1：AI 永远晚于 owner 的第一次 attempt（human prior → AI evidence → human update）
- P2：每个概念必须跨公司迁移（transfer test 强制）
- P3：考试日 AI 只能是 examiner，不提示不补全不安慰
- P4：终点是 skill diagnosis，不是研究报告数量

## 5. 对后续课程开发的具体建议

1. **时间估算必须先用 1–2 篇代表性材料实测校准，再推算全课时长**，不要用页数/字数线性估算。
2. **完成度核验必须设计成"读内容"而非"查字段"**——字段存在不代表内容质量达标，这是 v1/v2 都踩过的坑。
3. **多 agent 交接文档需要显式区分"规则层"和"设计层"两类信息**，规则层（欠账表、闭锁条件）容易被复述，设计层（当天 worksheet 里的强调点）容易被漏，交接提示必须包含 R7 清单里列的 6 要素。
4. **面向已有分析能力的学习者，练习设计应优先"结果已知、分阶段揭示证据"而非"完全开放选题"**——开放度不等于训练强度，反而会因缺少校准反馈而降低训练效果。
5. **理论材料与配套经典案例的阅读顺序需要显式设计**，默认"先理论后案例"可能污染独立判断这一核心训练目标，应视具体理论与案例的关系决定顺序。
6. **闸门类约束（如材料占比上限）在课程内容迭代后要重新用真实数字核算**，不能凭印象判断是否仍满足，且不允许"上调预算"来规避闸门——这会让闸门形同虚设。
